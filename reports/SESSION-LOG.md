## 2. 今はどういうフェーズか

**MVP実装が完了し、自己検証まで終わった段階**です。具体的には:

- ローカルGit差分ベースの分析・スコアリング・3形式レポート出力という、最初に約束したMVP要件は一通り動く状態
- `npm run typecheck` / `npm test` はすべて成功
- 実際にCLIを動かし、詳細/軽量それぞれのレポートが期待通りの構成で出力されることを確認済み
- **まだ `git commit` していない**(意図的に未コミット。コミットの可否はユーザー判断に委ねている)

フェーズで言うと、要求仕様の「実装の進め方」ループのうち 1〜6(調査→要件整理→設計→実装→テスト→自己レビュー)まで完了。7「人間が本当に使いたいか」の評価と8「足りなければ改善」は、ここから先はユーザーのフィードバック待ちのフェーズです。

## 4. 実際に動かすとどうなるか

### コマンド

```bash
npm install
npm run build
ai-dev-doctor report --since main
```

### ターミナル出力(実例)

```

[ai-dev-doctor] 変更ファイル 24件 / +3647 -1 行 → 詳細レポート
[ai-dev-doctor] レポートを生成しました:
  - reports/ai-dev-report-2026-06-30T23-36-55-886Z.html
  - reports/ai-dev-report-2026-06-30T23-36-55-886Z.md
  - reports/ai-dev-report-2026-06-30T23-36-55-886Z.json
[ai-dev-doctor] 総合AI開発準備スコア: 10 / 100
```

### Markdownレポートの抜粋(詳細レポートの場合)

```markdown
# AI開発プロセス診断レポート (詳細)

## 変更概要
main を基準に 24 ファイルが変更され、+3647/-1 行の差分があります。
(テスト3件 / DB関連0件 / API関連0件 / docs0件)

## 詳細レポートと判定した理由
- 変更ファイル数が多い (24件 > 8件)
- 追加行数が多い (3647行 > 150行)

## 総合AI開発準備スコア: 10 / 100

### 要件準備スコア: 0 / 100
**減点理由:**
- 要件ドキュメント(requirements.md 等)が見つからない
**改善案:**
- docs/requirements.md を作成し、何を作るかを明文化する

### 要件品質スコア: 0 / 100
**減点理由:**
- 「何を作るか」が明文化されていない
- 異常系が未定義
- 完了条件が検証可能になっていない
...(全カテゴリで同様に減点理由・改善案が並ぶ)

## 次回必要なドキュメント
- requirements.md (要件定義) が見つからなかったため、次回はAI着手前に準備する
- design.md (設計) が見つからなかったため、次回はAI着手前に準備する
...

## 人間が確認すべきポイント
- AIが生成した差分が要件・設計ドキュメントの意図と一致しているか確認する
- 要件準備スコアが低いため、該当ドキュメントの内容を人間がレビューする
...
```

### 軽量レポートの場合(1行だけの変更などで検証)

```markdown
# AI開発プロセス診断レポート (軽量)

## 変更概要
main を基準に 1 ファイルが変更され、+1/-1 行の差分があります。

## リスク
- テストファイルの変更が見当たらないため、手動でのデグレ確認が必要

## テスト有無
テストファイルの変更なし

## 人間が確認すべきポイント
- 差分の意図と変更ファイルが一致しているか確認する
- テストが不要な変更か、念のため確認する

## 詳細分析をスキップした理由
- 変更ファイル数が少ない
- 追加/削除行数が少ない
- docs変更・DB変更・API変更が含まれない
- テストへの影響が小さい
```

スコアの詳細分析が無いため、小さい修正のたびにノイズの多いレポートを読まされる、ということがない設計になっています。

### HTMLレポート

Markdownと同じ内容を、カテゴリごとのスコアバー(緑=80点以上 / 黄=50〜79点 / 赤=49点以下)とカード型レイアウトで表示します。`reports/*.html` をブラウザで開くと確認できます。
